# 🧪 LittleHands 测试计划（TEST PLAN）

> 版本：v1.2.0 · 用例总数：**71 项** · 一键执行：`bash backend/tests/run_tests.sh`

## 1. 测试目标

- 保证每次功能新增 / 调整后，**历史功能不回归、新功能行为正确**
- 全部用例自动化执行，人工仅负责体验性验证（动画、手感等无法自动化的部分）

## 2. 执行方式与环境

```bash
bash backend/tests/run_tests.sh        # 任意目录执行，约 40 秒
```

- 测试自动 **备份现有数据库 → 重置独立测试库 → 跑完全部用例 → 恢复原库**，绝不污染真实数据
- 无需网络（仅本机回环）；依赖：项目虚拟环境 `.venv`、`curl`
- 退出码：`0` 全部通过；`1` 存在失败（可直接用于 CI）

## 5. 准出标准（Definition of Done）

1. 五个阶段 **71 项断言全部通过（0 失败）**
2. 新增功能必须**同步新增对应用例**并更新本文档用例数
3. 涉及前端的行为变更需补充阶段 D 断言

## 6. 执行策略：三层自动防线

| 防线 | 机制 | 说明 |
|---|---|---|
| ① 本地一键 | `bash backend/tests/run_tests.sh` | 开发中随时手动执行，约 40 秒 |
| ② 推送拦截 | `hooks/pre-push`（`git config core.hooksPath hooks`） | `git push` 前自动全量执行，**失败阻止推送** |
| ③ 云端兜底 | `.github/workflows/tests.yml`（GitHub Actions） | push / PR 时云端自动执行，仓库页显示 ✅/❌ 徽章 |

> 新环境克隆后执行一次 `git config core.hooksPath hooks` 即可启用防线 ②。

## 7. 回归策略

- **每次功能新增或调整后，必须完整执行 `run_tests.sh`，全绿才算完成**
- 修复 bug 时：先写一个能复现该 bug 的用例（先红后绿），防止复发
- 发版前在干净环境（删除 `data/chore.db`）完整跑一遍，验证种子数据与首启动逻辑
